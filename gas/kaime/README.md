# 買い目シグナル — GAS（kaime-live）の設置手順

締切の約5分前に「風速」と「オッズ」を取りに行き、買い目を確定させる仕組みです。
GitHub Actions は数十分〜数時間遅れることがあるので、この部分だけ Google Apps Script（GAS）で動かします。

- 公開ページ：`https://072204nakamura-dotcom.github.io/marugame/kaime/`
- 候補JSON（毎朝5時半ごろ Actions が作る）：`https://072204nakamura-dotcom.github.io/marugame/data/kaime/targets/latest.json`
- このフォルダの `Code.gs` が GAS に貼るコード

---

## 最初に1回だけやること（ももやんの作業）

### 1. スプレッドシートを作る
1. Googleドライブを開く
2. 左上「＋新規」→「Googleスプレッドシート」
3. 左上の「無題のスプレッドシート」を押して、名前を **`買い目シグナル記録`** に変える

### 2. Apps Script を開く
1. スプレッドシートの上のメニュー「**拡張機能**」→「**Apps Script**」
2. 新しいタブでエディタが開く

### 3. コードを貼り付ける
1. GitHub で `gas/kaime/Code.gs` を開き、右上の「コピー」ボタン（四角が2つ重なったマーク）を押す
2. Apps Script のエディタに最初からある `コード.gs` の中身を **全部消す**（Ctrl+A → Delete）
3. 貼り付ける（Ctrl+V）
4. 上の「💾（プロジェクトを保存）」を押す

### 4. setup を実行する
1. エディタ上部の関数選択（「▶実行」の右の欄）で **`setup`** を選ぶ
2. 「▶実行」を押す
3. 「承認が必要です」が出たら →「権限を確認」→ 自分のアカウントを選ぶ
4. 「このアプリは Google で確認されていません」が出たら →「**詳細**」→「**安全ではないページに移動**」→「**許可**」
5. 画面下の「実行ログ」に `setup 完了` と出ればOK。スプレッドシートに `snapshots` `log` `settings` の3シートができている

### 5. テストする
1. 関数選択で **`testParse`** を選んで「▶実行」
2. 実行ログの最後に **`ALL OK`** と出ることを確認
   （`NG` や `FAILED` が出たら、そのログをクロちゃんに見せる）

### 6. トリガー（自動実行）を2つ付ける
1. エディタ左の **時計マーク（トリガー）** を押す
2. 右下「**＋トリガーを追加**」
   - 実行する関数：**`checkLive`**
   - イベントのソース：時間主導型
   - 時間ベースのトリガーのタイプ：**分ベースのタイマー**
   - 間隔：**5分おき**
   - 「保存」
3. もう一度「＋トリガーを追加」
   - 実行する関数：**`settle`**
   - イベントのソース：時間主導型
   - 時間ベースのトリガーのタイプ：**日付ベースのタイマー**
   - 時刻：**午前6時〜7時**
   - 「保存」

### 7. ウェブアプリとして公開する
1. 右上「**デプロイ**」→「**新しいデプロイ**」
2. 「種類の選択」の歯車 →「**ウェブアプリ**」
3. 次のユーザーとして実行：**自分**
4. アクセスできるユーザー：**全員**
5. 「デプロイ」→ 出てきた **ウェブアプリのURL**（`https://script.google.com/macros/s/…/exec`）をコピー

### 8. URLをクロちゃんに渡す
コピーしたURLをチャットに貼る。`kaime/index.html` の `GAS_URL` に入れて push してもらう。

### 9. 翌日に確認
- 朝：ページに候補が出ている（冬＝10〜3月以外は丸亀・芦屋・若松・津・福岡の×監視だけ）
- 締切の5分前ごろ：候補カードの「待機中」が「成立」「不成立（風Xm）」「見送り」のどれかに変わる
- 次の朝6〜7時のあと：スプレッドシートの `log` に前日分が入り、ページ下の「紙上成績」に数字が出る

## コードを直したとき

「保存」だけでは反映されません。

1. 右上「**デプロイ**」→「**デプロイを管理**」
2. 鉛筆マーク（編集）
3. バージョン：「**新バージョン**」
4. 「**デプロイ**」（URLは変わらない）

## シートの中身

| シート | 中身 |
|---|---|
| snapshots | 締切前の判定結果。1行＝1レース×1ルール。締切2分前までは上書き更新 |
| log | 紙上成績。翌朝の settle が結果・払戻を書く。KIR-A・TOD-A は確定オッズも `final_odds` に残す |
| settings | `unit`＝1点あたり金額（初期100円）。紙上成績の計算に使う |

- `status` は 成立／不成立（風が5m未満）／見送り（40〜80倍などに当てはまる目がない）／保留（取得できず次の回で再挑戦）
- `log` の `hit` は 1＝的中、0＝外れ、返還＝レース中止（投資額を払戻として戻す）
- シートは手で書き換えない（特に snapshots の1〜4列目はキー）

## 困ったとき

- **ページに「判定なし（締切まで取得できず）」が並ぶ**：トリガーが止まっている可能性。Apps Script 左の「実行数」でエラーを見る
- **候補が朝のうちに出ない**：GitHub Actions が遅れている（混雑で数時間遅れることがある）。GitHub の Actions →「kaime-targets」→「Run workflow」で手動実行できる。桐生の1Rは15時ごろ締切なので、それまでに候補が出ていれば間に合う
- **ルールの条件は変えない**。変えると過去3年の検証が無意味になる（`scripts/kaime/rules.py` と `Code.gs` の RULES は同じ内容）
