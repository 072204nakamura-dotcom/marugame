## 3. データ取得・パース仕様（コードレベル）

### 3-1. Bファイル（番組・毎朝の入力）

- URL：`https://www1.mbrace.or.jp/od2/B/{YYYYMM}/b{YYMMDD}.lzh`（LZH・Shift-JIS。`pip install lhafile`で解凍）
- 宮島ブロック：`raw.split("17BBGN")[1].split("17BEND")[0]`
- 節タイトル・日目：NFKC正規化後 `第\s*(\d+)\s*日`。冒頭行の `ボートレース宮\s*島\s+\S+\s+(タイトル)\s+第`
- レースヘッダー（NFKC後）：`^\s*(\d+)R\s+(レース名)\s+H\d+m\s+電話投票締切予定(\d{1,2}):(\d{2})`
- **選手行の桁位置（要注意・実地デバッグ済み）**：
  ```
  line[0]     = 艇番(1-6)
  line[1]     = 半角スペース（これで選手行を判定）
  line[2:6]   = 登番4桁
  line[6:10]  = 選手名（全角4文字）
  line[16:18] = 級別（A1/A2/B1/B2）
  line[18:]   = split() → [全国勝率, 全国2率, 当地勝率, 当地2率, モーターNO, モーター2率, ...]
  ```
- 6艇そろったレースのみ採用。優勝戦日判定＝その日のレース名のどれかに「優勝」を含む。

### 3-2. Kファイル（結果・テーブル再生成時のみ使用）

- URL：`https://www1.mbrace.or.jp/od2/K/{YYYYMM}/k{YYMMDD}.lzh`。ブロックは`17KBGN`〜`17KEND`
- フィニッシャー行の桁位置：
  ```
  line[0:2]="  "(空白2) / line[2:4]=着順 / line[6]=艇番 / line[8:12]=登番
  line[21:].split() → [モーター, ボート, 展示, 進入コース, ST, レースタイム]
  ```
- **レース数の数え方は「総エントリー÷6」**（ヘッダー正規表現は冒頭の払戻一覧と二重計上するため不可）
- 3連単配当はブロック冒頭の払戻一覧 `^\s*(\d+)R\s+([1-6]-[1-6]-[1-6])\s+(\d+)` の**初出のみ**採用

### 3-3. 取得の作法

- 並列DLは `xargs -P 8〜10`、UA付与（`Mozilla/5.0`）、既存ファイルはサイズ>1000bytesでスキップ、失敗時（<1000bytes）は削除してリトライ可能に。

## 4. スコアリング仕様（build_miyajima.py・現行ロジック）

```
score = RNO_SCORE[rno]
RNO_SCORE = {1:-4.0, 2:+1.0, 3:+1.5, 4:0, 5:+1.5, 6:-1.5, 7:+2.5,
             8:0, 9:+0.5, 10:0, 11:-1.0, 12:-1.0}   # §1-2実測残差ベース
if 優勝戦日: score -= 2.0
1号艇について:
  逃げ率<45: +2.0（バッジ「イン不安」）／ <50: +1.0
  逃げ率>65: −2.0（バッジ「逃げ厚」）／ >60: −1.0
  F持ち(f_holders.csvに登番あり): +1.5（バッジ「F持ち」）
  平均ST≥0.19: +1.5（バッジ「ST遅め」）
3・4号艇: 平均ST≤0.14 → +0.8（バッジ「ST一撃」）
5・6号艇: 級別A1 → +0.7（バッジ「外に地力」）
ラベル:
  rno==1 かつ score<=0 → 「鉄板1R」
  score>=4   → 「穴の巣」
  score>=2   → 「堅いか万舟」
  score<=−3  → 「イン堅め」
  それ以外    → 「中間」
```

方針文：ラベル別定型＋全レース共通の直前確認文「北東/東の風2m以上なら穴側へ加点（−5.8pt効果・暫定採用）」。
**スコア定数の変更は、統計再検証（三条件）を通してから**。感覚での調整は不可。

## 8. ガードレール（Claude Codeへの禁止事項）

1. **潮位・潮流・干満データをいかなる形でも実装に足さない**（§1-4。検証済み無効。「広島は干満差が大きいから」という直感は本検証で否定済み）
2. 初日加点・6コース厚買いなど**他場フォームの無断転用禁止**（宮島は逆特性）
3. スコア定数・ラベル閾値の**感覚調整禁止**（変更は統計再検証とセット）
4. ファイル名は半角英数字・CSVはBOM付きUTF-8を維持
5. data.jsonの既存フィールドを壊さない（§5）
6. オッズ収集の重複実装禁止（既存システムが蓄積中）
7. Actionsのcronは `0 22 * * *`（JST7:00）を維持——他場と同時刻でmbraceへの負荷を1回に集約
